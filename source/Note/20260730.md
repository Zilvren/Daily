## redis学习

### SDS

```c
struct sdshdr {

    // 记录 buf 数组中已使用字节的数量
    // 等于 SDS 所保存字符串的长度
    int len;

    // 记录 buf 数组中未使用字节的数量
    int free;

    // 字节数组，用于保存字符串
    char buf[];

};
```

当$SDS$需要空间拓展的时候，分两种情况

* $SDS<1MB$，会预分配给$SDS$所需字节$len$的两倍字节$+1$，此时$len = free$，额外$1$字节的空间

* $SDS>=1MB$，会固定额外分配给$SDS$，$1MB+1B$的空间

$SDS$需要缩短字符串时，是惰性空间释放，即程序不立即回收空间，而是增加$free$值，等待将来使用

“二进制安全”（Binary Safe）指的是：系统处理数据时，把它当作任意字节序列，而不是以某个特殊字符作为结束或控制标记

而$redis$用$len$来标记字符数据的结束，是二进制安全的



比起 $C$ 字符串， $SDS$ 具有以下优点：

1. 常数复杂度获取字符串长度。
2. 杜绝缓冲区溢出。
3. 减少修改字符串长度时所需的内存重分配次数。
4. 二进制安全。
5. 兼容部分 $C$ 字符串函数。
